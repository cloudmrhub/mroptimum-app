MR Optimum Mode 2

A simple setup, deployment, verification, and teardown guide for Windows, macOS, and Linux.

Requirements IAM setup AWS profile Install Deploy Teardown Remember

Workflow at a glance

  1. Confirm CloudMRHub login
  2. Create IAM user
  3. Create AWS access key
  4. Configure profile
  5. Install manager
  6. Deploy and verify
  7. Teardown when finished
AWS console credentials and AWS CLI access keys are separate. A console password does not create an Access Key ID.

1. Requirements

Every user needs a working CloudMRHub account, an AWS account, an approved IAM deployment user, Git, Python 3.9+, AWS CLI v2, internet access, and an AWS VPC subnet with outbound internet connectivity. Docker is not required locally.

Windows

Windows 10/11, PowerShell, Python through py or python.

macOS

Terminal, python3, Git, and AWS CLI v2.

Linux

Bash or another shell, Python 3 with venv and pip, Git, and AWS CLI v2.

2. Know which credential goes where

CredentialUsed whereHandling
CloudMRHub emailDeployment command and web loginRemember it
CloudMRHub passwordHidden deploy/teardown promptUse a password manager
AWS console loginAWS website onlyStore securely
Access Key ID + Secret Access Keyaws configureSave securely; never share
Worker API keyGenerated automaticallyProtect the local config

3. Create the IAM user and access key

  1. Open AWS Console → IAM → Users → Create user.
  2. Create a dedicated user such as mroptimum-mode2-user.
  3. Assign the administrator-approved Mode 2 deployment permissions.
  4. Open the user's Security credentials.
  5. Under Access keys, select Create access key.
  6. Choose Command Line Interface (CLI).
  7. Create the key and securely download the CSV.

The user needs CloudFormation, IAM role/pass-role, EC2 discovery/security-group, Lambda, API Gateway, ECS/Fargate, S3, CloudWatch Logs, EventBridge, and STS identity permissions.

Never use AWS root credentials. The Secret Access Key is displayed only once and must never be placed in GitHub, CloudMRHub, email, or chat.

4. Create and verify the AWS CLI profile

aws configure --profile mroptimum
AWS Access Key ID: <ACCESS_KEY_ID>
AWS Secret Access Key: <SECRET_ACCESS_KEY>
Default region name: us-east-1
Default output format: json

Verify the selected AWS identity:

aws sts get-caller-identity --profile mroptimum

5. Install MR Optimum

Windows PowerShell

git clone https://github.com/cloudmrhub/mroptimum-app.git
Set-Location mroptimum-app
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install boto3 requests

macOS or Linux

git clone https://github.com/cloudmrhub/mroptimum-app.git
cd mroptimum-app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install boto3 requests

6. Deploy Mode 2

Windows

python -X utf8 worker/manage.py deploy --profile mroptimum --email <CLOUDMR_EMAIL> --alias "<WORKER_NAME>"

macOS or Linux

python worker/manage.py deploy --profile mroptimum --email <CLOUDMR_EMAIL> --alias "<WORKER_NAME>"

Press Enter to accept us-east-1. At CloudMR password, enter the existing CloudMRHub password—not an AWS password or access key.

Windows uses -X utf8 to prevent the current manager's template-reading UnicodeDecodeError.

Verify

# Windows
python -X utf8 worker/manage.py status --profile mroptimum

# macOS/Linux
python worker/manage.py status --profile mroptimum
A working deployment reports CREATE_COMPLETE, an API endpoint, and Health: OK. Refresh MR Optimum and select the new worker alias.

7. Logs, costs, and updates

Add -X utf8 after python on Windows.

python worker/manage.py logs --profile mroptimum --follow
python worker/manage.py costs --profile mroptimum
python worker/manage.py update --profile mroptimum

8. Tear down Mode 2

Always use the manager. It deregisters the computing unit from CloudMRHub, empties temporary payload storage, deletes the AWS stack, and removes the local Mode 2 configuration.

Windows

python -X utf8 worker/manage.py teardown

macOS or Linux

python worker/manage.py teardown

Confirm with y and enter the CloudMRHub password. Refresh the web application after successful deregistration.

Do not delete the CloudFormation stack directly unless you are prepared to remove the stale computing-unit entry manually.

9. Save and remember

  • The AWS profile is named mroptimum.
  • AWS CLI credentials are stored in %USERPROFILE%\.aws\credentials on Windows or ~/.aws/credentials on macOS/Linux.
  • The worker configuration is stored in ~/.mroptimum/config.toml.
  • Protect the CloudMRHub password, AWS access keys, and generated worker API key.
  • Rotate or delete unused IAM access keys.
  • Use the manager's teardown command so AWS deletion and CloudMRHub deregistration happen together.

Troubleshooting

  • Access key age is blank: create an access key under the IAM user's Security credentials.
  • Unable to locate credentials: rerun aws configure --profile mroptimum.
  • AccessDenied: the IAM deployment permissions are incomplete.
  • UnicodeDecodeError on Windows: use python -X utf8.
  • Worker remains visible: confirm teardown reported successful deregistration, then refresh MR Optimum.
